# 快科研 Rapid

## 开工

1. 明确用户要拿到的产物、范围和资源预算。把下表对应的步骤列成短清单。用户指定单步时，以该步交付物为终点。
2. 续做时先读已有交接、实际稿件、结果、配置和运行状态。逐项核对仍适用的产物，记为「复用」并指向来源。从最早缺失的必要产物接着做。已有任务在跑时接管其结果收集，按原运行 ID 或日志跟踪。

| 用户要的产物 | 默认路线与退出条件 |
|---|---|
| 选题或研究计划 | 1 → 2 → 3 的计划分支。交付能区分主张的最小实验、预算和判读规则。 |
| 从结果出初稿、图或完整稿 | 3 的结果分支 → 4。需要支撑 novelty 时补 2。完整稿走 5 的一次审稿返修。交付指定范围的稿件、图和证据来源。 |
| 审稿或返修 | 从 5 开始。审稿交付按证据定位的意见，返修回到受影响的步骤，交修订稿和剩余意见。 |
| 投稿包、预印本或 camera-ready | 从 6 开始，补齐当前稿件和目标 track 缺少的材料。交付实际渲染的 PDF 和完整提交文件。 |

从 idea 开始且需要实测时，先按 3 的计划分支定预算。用户只要方案时，交计划和能写的部分，标明待测结果。用户授权执行时，先解决可恢复的依赖问题，再跟到结果可用。等结果期间推进能独立完成的内容。

## 选择 skill

用户点名时按用户选择。默认按 playbook 的条件选一条主路线，按需加载互补 skill。只读选中分支的固定版本 `SKILL.md` 和必要参考文件。优先用项目现有工具，也可用当前环境的等价能力。上游的实验、审批和 reviewer 默认设置以当前交付范围、用户授权和预算为准。

## 推进与回退

1. 用各步的完成条件核实际产物，再把它交给依赖它的步骤。图表、写作和审稿共用同一份主张与证据记录。遇到依赖缺失时，照常推进能独立完成的部分。
2. 返修只回到最早受影响的一步。主张或最近前作变了，核对应的查新、baseline 和证据。结果变了，更新引用该结果的正文、表图、附录和复现入口。只改措辞时复用证据，检查改动段落。换 venue 时按新要求重做受影响的材料。
3. 每轮解决一组明确问题，再核变更是否解决它。达到目标就交付。若后续需要新证据、预算或外部操作，留下具体缺口、已完成产物和接续点。长任务用现有记录保留当前版本、仍在运行的任务及恢复入口，供下次继续。
